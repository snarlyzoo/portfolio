# 00 — Overview & strategic direction

## Who / what

SnarlyZoo — a systems-focused Roblox developer. Portfolio currently lives at `snarlyzoo-portfolio.vercel.app` (Next.js 14). This rebuild creates a new repo (`snarlyzoo/portfolio`) with a **completely fresh visual design**.

## The catalyst: job rejection feedback

The user was a finalist for a Roblox gameplay-engineering role and was rejected. The studio's detailed feedback (paraphrased):

- The work **stood out**; technical knowledge and **ability to build/structure systems were already evident** and never the problem.
- The chosen candidate had similar strengths **plus several completed games and more presentation-focused visual showcases**.
- Advice: expand the portfolio with **more visual work — UI, particle effects, animations, polished/complete game projects**.
- Crucially: **applications are often reviewed primarily by non-programmers**, so "professional-looking UI, animations, particle effects, and overall presentation can have a significant impact on how your work is perceived."
- Suggested developing those skills, **collaborating with artists, and/or purchasing assets**.

## The strategic pivot

The takeaway: **do not double down on the existing strength (deep code).** Invest in the gap — **visual polish and presentation** — while keeping the technical depth as a supporting layer.

Concretely:

1. **The site becomes visual-first.** Each project page opens with video → UI/VFX showcases → screenshots, and the code/file-tree/systems write-up sits below for technical readers who scroll.
2. **The site itself is a presentation artifact.** A non-programmer judges the website too — so the new design must look polished and engaging on first impression.
3. **Surface existing UI/VFX as visuals.** The user already built animated HUDs (power-meter shake, spring health bars, marching trajectory previews) and VFX (muzzle flash, beam pools, particle emitters). These were described as *code*; they need to be *shown* as GIFs. High impact, low cost.
4. **Quick in-game polish, not new systems.** Small additions (particles, trails, post-processing, screen shake, UI juice) make existing projects *look* polished. See [03-project-polish-plans.md](03-project-polish-plans.md).
5. **Completeness later.** Not shipping an old game. `brickbattle-turf-wars` is the intended future flagship to showcase once it has real gameplay.

## What this rebuild is NOT

- Not a single-job application. Remove all role-targeted framing ("Relevance to Position", "Coverage vs. Job Requirements" matrix, the gaps/weaknesses list).
- Not diagram-heavy. Box-and-line system diagrams were explicitly rejected as cluttered.
- Not AI-art-decorated. AI key art undercuts credibility with a Roblox-literate audience.
